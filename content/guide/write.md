# 怎么写

这篇说明如何登录、上传和保存。阅读不需要令牌。写入只发生在 `content/` 下面。

## 登录

1. 点击右上角「登录」。
2. 打开 GitHub → Settings → Developer settings → Fine-grained tokens。
3. 只选择这个仓库。Repository permissions 里把 Contents 设为 Read and write。Metadata 的只读权限会随 Contents 自动带上。给令牌设一个到期日。
4. 把以 `github_pat_` 开头的令牌粘贴到密码框。其他格式不会被保存。
5. 令牌只留在这台浏览器里。退出只删除本地保存，不会通知 GitHub。

令牌无效或已经撤销时，页面会要求重新登录。没有写入权限时，页面会提示把 Contents 设为读写。

## 上传

登录后可以使用「上传文件」和「上传文件夹」。

- 单个文件放到当前文章所在的目录。
- 文件夹会保留相对路径，接到 `content/` 后面。
- 只能上传 Markdown 和 png、jpg、jpeg、gif、webp。单文件超过 1 MB 会在发出请求前被拒绝。
- 如果路径已经存在，会先列出清单。确认之后按更新处理，并带上现有文件的标识。
- 多份文件排成队列，上一份完成后再发送下一份。中途失败会停住，已经成功的保留下来。

## 保存

打开一篇文章，点击「编辑」。右侧是原文编辑器，不会重排 Markdown，也不会擅自补换行。

按 `Ctrl+S` 或 `⌘S`，和点击「保存」是同一条路径。正文相对打开时有改动时，离开页面前会先询问。

新建时填写相对 `content/` 的路径，并且以 `.md` 结尾。初始文本是一个一级标题和空行。路径已经存在时，会打开那一篇，而不是直接覆盖。

删除前会要求确认。删掉当前正在看的文章后，会跳到目录里相邻的一篇；没有相邻篇时回到首页。

## 冲突

如果 GitHub 网页上刚刚改过同一文件，再在这里保存，页面会提示文件刚刚被改过，并重新拉取这一份的标识和正文。编辑器里还没保存的文字会留下。请再保存一次。页面不会用旧标识自动重试，以免盖掉中间那次写入。

> [!warning] 路径
> `content/../src/main.ts`、`src/main.ts` 和 `content//a.md` 都不会发出请求。

> [!note] 原文
> 保存写入的是编辑器里的原文。标注、公式和双链只在阅读时呈现。
